# 6.0.0

## Minecraft 1.21.11

- **Ported to Minecraft 1.21.11** (Fabric Loader >= 0.20.1, Fabric API 0.141.6+, owo-lib 0.13.0, Mod Menu 17.0.1). This release also contains everything that was in development for 5.0.0.
- **Game rules are now snake_case.** `gestorage:enderChestSize`, `gestorage:stackableShulkers` and `gestorage:hopperStackableShulkers` became `gestorage:ender_chest_size`, `gestorage:stackable_shulkers` and `gestorage:hopper_stackable_shulkers`. 1.21.11 stores game rules in a registry keyed by identifiers, and identifier paths cannot contain uppercase letters (vanilla renamed every one of its own rules the same way), so the old names can no longer be registered.
- **Existing worlds keep their settings.** The values saved under the old names in a 1.21.1 world are imported into the new rules the first time the world is opened. The import runs once per world, so a later `/gamerule` change is never overwritten. Vanilla logs the old keys it has to drop while opening the world once; that is expected and harmless.

## Added

- **Careful Break is now per player.** Each player owns the eight toggles (Enabled, Careful Break, Careful Drop, Always Careful, Tree Capitator, Better Harvesting and both Auto Replant options), stored by UUID in `config/gestorage/careful_break.json`, so one player's keybinds no longer change anyone else's gameplay and fake players are never affected. Only operators, the singleplayer host and players an operator permits can change their own copy; without permission the options are shown off and have no effect. Existing global settings from 6.0.0 pre-release builds are reset to off, so each player opts in again.
- **New `/gestorage careful` commands:** `allow <players>` and `deny <players>` grant or revoke permission per player (deny also turns their saved options off), `allowall [on|off]` grants it to everyone, and `list` reports the current permissions (all OP level 2).
- **Inspector module (off by default):** hold a configurable key (or use Toggle Mode) to preview the live contents of the inventory under your crosshair, inside one framed panel with the target's own icon beside its name. Blocks and entities are resolved on the server from the client's vanilla crosshair selection, so chests, hoppers, shulker boxes and storage minecarts all work. An optional **Show Info Box** draws a small panel above the preview with the target's name, id, position, block state properties or health, and inventory size; it also works on blocks and entities without an inventory. Settings live in `inspector.json5`.
- **Slot Lock** module: hold a configurable key and left-click a slot to lock it.
  - Lockable slots: the whole player inventory (main inventory, hotbar, armor and offhand) and the ender chest while it is open.
  - Holding the key outlines lockable slots in yellow; locked slots keep a red outline.
  - Options: sorting skips locked slots, prevent drop, and prevent use (right-click use and block placement; attacks and opening containers/doors are unaffected).
  - Locks are stored per player and per world, are server-authoritative, and do not stop normal item movement.
- **Shulker Restock: reversible refill order** — you can now choose whether items are pulled out of the shulker box from the first slot to the last (the default) or from the last slot to the first. Toggle it with the `Reverse Order` option in the module settings or its own assignable keybind; the server honours your choice in the `refill_request` packet.
- **Config screen: real translucency, no extra mod required.** The settings menu's window, buttons and checkboxes have always shipped with semi-transparent artwork, but the vanilla draw path never enabled alpha blending on them, so an external mod (Translucency Fix) was needed to see through them. Gestorage now renders them blended, so the menu blends with the world behind it out of the box.
- `gestorage:hopper_stackable_shulkers` game rule (default `false`): when enabled, hoppers and hopper minecarts stack empty shulkers while `gestorage:stackable_shulkers` is also enabled. Hopper stacking is independent from player stacking and stays off unless explicitly enabled.
- `/gestorage shulkerstack players [on|off]` and `/gestorage shulkerstack hoppers [on|off]`; the no-argument form reports both states. Turning hoppers on also enables player stacking if it was off, because the main rule is required.

## Changed

- `/gestorage shulkerstack` was simplified to the `players` and `hoppers` subcommands; the old bare `on`/`off` and `true`/`false` aliases were removed.
- With hoppers off, a hopper only moves empty shulkers into empty slots, so a destination chest with one shulker in every slot is treated as full. Enabling hoppers lets them merge into existing stacks instead.
- The shulker state packet now mirrors both the player and hopper rules, so client-side GUI limits match the server instead of predicting a stack the server will reject.

## Fixed

- **Storage Overlay, the sorting button and slot-lock highlights now appear in the player inventory, crafting table and furnace screens.** Those screens render through `RecipeBookScreen`, which calls `renderMain` directly and never ran the hook on `render`, so the overlay was missing exactly where it was most used.
- **Storage Overlay: the Inventory Name and Item Name options now work while the item icon is on.** Icon mode used to force the item name on and suppress the inventory title, so both options did nothing at their defaults; each line now follows its own toggle, and the icon gets its own row when no name line is shown.
- **Config backups are now actually created.** The backup helper looked for `.json`, but owo writes `.json5`, so no backup was ever written. Each module config is now copied to `<name>.json5.backup` on startup before it is loaded.
- Careful Break config loading is now defensive: a malformed or non-boolean field no longer aborts the whole load, and missing values fall back to off.
- **Auto Replant now handles pale oak trees.**
- **Auto Tool: a different tool of the same item moved into the tool slot is no longer rotated into the wheel.** The pending swap now checks the exact stack that was swapped in (ignoring durability used while mining) instead of matching by item only.
- **Shulker Restock: per-link client state is now pruned every tick**, so replacing a link with another one no longer leaves a stale entry behind.
- A hopper picking up a dropped stack of empty shulkers while hopper stacking was off could delete most of the stack: the whole entity stack was copied, the destination capped it to 1, and the entity was discarded. The pickup now moves at most the effective limit and leaves the remainder in the item entity.
- Hopper-rule bypasses through item-entity collision and hopper minecart ticks were closed; both now run inside the hopper context. Shift-clicking or manually inserting into a hopper screen is also capped to one shulker per slot while hopper stacking is off.
- Empty shulkers carrying a loot table (`CONTAINER_LOOT`) were treated as empty and could stack, which risked duplicating structure loot when placed. They are now always treated as non-empty.
- The hopper transfer context is now reentrant and always cleared in a `finally` block, so nested hopper calls or an exception can no longer leave the server thread marked as a hopper.
- Turning player stacking off now splits existing over-max empty-shulker stacks in the player inventory, cursor and ender chest into singles, dropping the overflow at the player's feet. The same normalization runs on join, and the extended ender chest is normalized when it is opened.
- Modded shulkers with a custom `MAX_STACK_SIZE` now keep their own limit instead of being forced to 64.
- Lithium's cached full-slot count is now invalidated when either shulker rule changes, so toggling hopper stacking no longer leaves hoppers stuck (or over-eager) until the inventory changes.
- A legacy over-max destination stack can no longer corrupt a hopper transfer: vanilla's merge calculation subtracts a negative amount when the destination already exceeds the limit, so slots at or over the limit are skipped.
- A hopper chain no longer stops after the destination chest is emptied while hoppers are off. Empty shulkers are max 1 only during the hopper transfer, which made Lithium's cached full-slot count treat each single as full; removing them with the player limit of 64 never decremented that cache, including when shift-clicking or manually taking stacks changed the count in place. The compatibility mixin now applies the same effective limit whenever Lithium updates its cache, so the hopper resumes as soon as a slot is cleared.
- **Shulker Restock: the hotbar count no longer looks like it is being consumed when refilling blocks.** Placing a block is predicted on the client (the stack is decremented locally), so when a refill restored the count to the very number the server had already sent, the correction was never pushed and the client kept counting down while the server stayed full. The server now forces the corrected stack back to the client after a refill, so blocks behave like rockets and every other item.
- **Shulker Restock: the forced client update no longer creates ghost stacks in unrelated slots.** The correction packet used the raw player-inventory index, but the player screen handler shifts the hotbar, armor and offhand slots (its slot 0 is the crafting result). Restocking hotbar slot 0 showed a phantom stack in the crafting result, hotbar slot 6 showed one in the chestplate slot, and the real slot stayed below 64. The index is now mapped to the player screen handler before the packet is sent, so the correct slot is refreshed and no item is duplicated on the client.
- **Tool Wheel: Auto Tool now always swaps into the pinned Default Slot.** Previously it only moved your hand when it had to change the tool, so when the tool already in your hand was the right one for the block it left your selection untouched and the Default Slot was ignored. Auto Tool now selects this slot on every mine start, whether or not an item swap is needed.
- Extended ender chest overflow is now saved at most once every two seconds per player instead of on every refill request, which could force repeated world saves. Closing the ender chest still saves immediately, and refill still keeps target stacks topped to 64.
- The ender chest overflow NBT is backed up once per session before it is first read, so a first write can no longer overwrite the only recoverable copy.
- **Modifiers can now be bound as standalone keys in every module.** Pressing and releasing a single modifier while capturing (for example Left Alt) binds that exact side as the key, stored as `left_alt`; holding a modifier and pressing another key still creates a combination. Previously the config screen swallowed modifiers, and even a hand-edited modifier-only binding was rejected at runtime because the modifier was treated as an extra prefix. All keybinds also work while holding unrelated modifiers now: runtime checks require the configured modifiers but no longer reject extra ones, so sneaking with Shift no longer blocks Inspector, Slot Lock, Tool Wheel or any other module.
- **Inspector is now symmetric and uses the mod's own translucent GUI texture.** The inventory grid, optional info box, slots and target icon all reuse `panel.png`, so the preview matches Storage Overlay and the config screen. Both panels share one computed width and center, instead of being centered independently when the info lines were wider than the grid. The target's icon (picked block item or entity spawn egg) now appears beside its name.
- **Inspector now reacts immediately when you aim at a block.** The server used to repeat the client's raycast with its own rotation, which is one tick older, and silently dropped the request whenever the two disagreed; the client then waited half a second for the next refresh. The server now trusts the vanilla crosshair selection and only resolves the reported target, unanswered requests are retried after three ticks, and the last 32 targets per dimension are cached so looking back at a container shows its contents instantly. A first-time target shows a `Loading...` placeholder instead of an empty panel.
- **Inspector now shows complete double chests.** Aiming at either half resolves vanilla's combined inventory, so the preview always shows all 54 slots instead of the 27 slots of the half block entity. Both halves work as inspection targets and show the same full contents. Chest lookup now ignores solid blocks or cats sitting above the chest, which could otherwise make vanilla return only the targeted half or no inventory at all.
- **Inspector no longer sticks on `Loading...` at random.** Every retry used to increase the request id, so on a server with normal latency the first reply arriving after three ticks was discarded and the client kept invalidating all later replies. Retries now reuse the same id, requests have a real timeout, and targets without a valid reply get an empty response instead of silence. Target keys also include the dimension. Long custom names are trimmed to the packet's UTF-8 byte limits so they cannot break encoding.
- **Inspector now detects containers such as hoppers from any angle.** The server used to repeat the client's crosshair raycast, but blocks like hoppers have a direction-dependent raycast shape and the server's eye and rotation are one tick older, so the same hopper worked only from certain angles. The server now trusts the vanilla crosshair selection, so if you can select the block or entity you can inspect it.
- **Inspector now reads mob and player inventories.** Villagers, piglins, pillagers and allays keep their items in an `InventoryOwner`, while players and fake players use `PlayerEntity.getInventory()`; none of them implement `Inventory` directly, so they were reported as empty. **Tweakeroo freecam is now supported as well:** the server no longer rejects targets for being far from the player's body, and when Tweakeroo's `freeCameraPlayerInputs` option forces vanilla's crosshair back to the player, the Inspector does its own pick from the camera entity so the preview follows the camera view.
- **Inspector slots no longer look like separate white squares.** The translucent panel is now drawn once around the whole grid, so only one border marks the inventory limits and items sit together inside it.
- Careful Break now handles nested deaths correctly: an inner death without a player killer no longer clears the outer death context, so later drops from the outer kill are still collected.
- Legacy (version 0) shulker link files with a malformed entry now skip only that entry instead of discarding every link.
- The server now pushes the ender chest size to clients on join and whenever `gestorage:ender_chest_size` changes (including a plain `/gamerule`), not only when an ender chest is opened.
- Tool Wheel sync now also reads state that is still pending in memory, so a change made before the next world save is no longer sent to the client as empty.
- **Game rules now apply from every dimension.** 1.21.11 stores game rules per world, but `/gestorage endersize` and `/gestorage shulkerstack` were writing the current dimension's copy while the mod read the overworld's copy, so running them in the Nether or the End reported success without changing anything. Gestorage's rules keep their 1.21.1 server-wide meaning and always read/write the overworld copy; opening an ender chest uses the same rules.
- **Careful Break toggles now run on the server thread.** The client toggle packet used to save the config and broadcast its state directly on the network thread, unlike every other C2S handler.
- **Tree Capitator no longer destroys a neighbouring tree's canopy.** A leaf still within leaf-decay range of a log outside the felled tree is left in place instead of being removed with the harvested tree.
- **Shulker Restock detects shulker boxes more reliably.** Vanilla shulker boxes are recognised by their block type and modded ones by a strict block-id match, so unrelated ids containing `shulker_box` are no longer treated as shulkers.
- Ender chest overflow data now rejects unknown or newer save versions and starts fresh, instead of loading a format it does not understand.
- The Careful Break keybind file is now versioned; an unknown version resets to defaults instead of being read as the current layout.
- Opening the settings screen from Mod Menu and toggling a server-side option (Careful Break, Auto Tool or the enchantment preference) without joining a world no longer crashes the game. Client packets are only sent while connected, and those options are disabled until a world is joined.

## Compatibility

- Client and server must both run 6.0.0: Slot Lock and Inspector add new packets, the Inspector reply carries the target icon at the end of its payload, the shulker state packet carries both the player and hopper rules, the refill packet carries the refill-order field, and the game rule names changed.
- Lithium is optional and supported. No Lithium classes are required at runtime; the compatibility mixin is skipped when Lithium is not installed.
